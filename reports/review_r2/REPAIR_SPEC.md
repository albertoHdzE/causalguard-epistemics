## A. Reliable ownership, interruption and immutable attempts

Own `runner.py`, `freeze.py`, runner/fixture tests and associated execution documentation.

1. Obtain exclusive per-run execution ownership before opening recovery paths, quarantining files, scheduling work or allocating an attempt. Refuse a second active execution deterministically. Release ownership on normal termination and handle crashes without allowing a stale lock to permanently block recovery. Use OS-supported ownership where practical; a PID alone is not a durable identity because it can be reused. Do not kill unrelated processes.
2. Publish terminal attempts without replacing an existing result. Keep exact successful bytes; preserve failed/superseded attempts and recovery evidence. Synchronize any shared registry recovery/writes enough that separate approved studies cannot truncate or corrupt each other's ledger entries.
3. Ensure hard supervisor death terminates/reaps or otherwise safely accounts for its worker groups and descendants within a declared bound. A portable watchdog/parent-liveness design is acceptable. Establish ownership before scientific work and protect the startup/death/resume races. A live parent enforcing deadlines is not sufficient. Immediate resume must not overlap old computation.
4. Derive end status and run-level counts from all latest attempts, with separate invocation counts. Failed terminal items remain failures after no-op resume. Expose the same status in the CLI/access ledger and analysis. Distinguish execution termination from the study's completeness policy.
5. Do not retry successful outcomes. S1 query timeouts/resource limits are scientific outcomes, not retry opportunities. Default S2 unresolved failures leave its primary incomplete. If implementing a confirmatory retry facility, freeze a bounded infrastructure-only policy before approval, preserving every attempt and the original identity; never retry selectively based on scores or alter a salt/configuration to force success.
6. Use one strict validator for persisted plans and every attempt at resume and read time. Recompute plan/config/payload digests; validate schema, identities, statuses, numbering, supersession and study linkage. Validate before mutating storage; distinguish a permitted torn temporary tail recovery from internally inconsistent scientific data.

Acceptance tests: deterministic concurrent resumes (one owner; one successful attempt; original bytes intact); hard parent-group kill with a hanging worker and descendant; prompt cleanup and immediate safe resume; normal interruption mid-write; failure followed by no-op resume; permitted explicit failed retry if provided; altered stored plan; wrong run/plan/source/payload on any attempt, including superseded failures. Retain scoped preflight, external runtime and cross-study fixture lifecycle tests on macOS and Ubuntu. Test only temporary `FIXTURE-NONCONFIRMATORY` repositories, never production confirmation.

## B. Scientific completeness and phase-aware reporting

Own study analyses and their tests; coordinate the metadata interface with A.

1. Reconcile each output with its planned world and study. S2 must have all expected primary cells, exactly 16 distinct intervention-query identities, and the expected state-query grid. Validate against the versioned design rather than merely counting arbitrary rows. Reject duplicates, wrong world/design/regime/budget identities, malformed values and inconsistent count/tie/verdict fields. Preserve declared empty-version-space/invalid-prediction semantics; an absent query is not that declared outcome.
2. A nominal `ok` attempt missing a primary cell cannot produce a completed primary. Return a clear refusal or explicit incomplete result with bounded missing-outcome accounting. Do not silently reduce N, query counts or family weights. Handle zero completed worlds and a whole missing family without crashing or emitting misleading NaNs.
3. Report structured-primary, required-null and overall-study planned/complete/failed/missing status separately. A valid structured estimate may be available before the null finishes, but the overall study is incomplete. Apply analogous reconciliation to S1's expected query grid, exclusions and failed items; status `ok` does not license silently absent queries.
4. Preserve attempt envelope resource metadata through validated loading. Correct S1 RSS using the stored measurements; missing metadata must be null/explicitly missing, never zero. Report coverage and measurement units. Regenerate corrected derived reports without rerunning measurements.
5. Distinguish development, fixture and confirmatory reporting from validated provenance, including titles and machine-readable status. Refuse ambiguous mixed phases where necessary. Development sizing is an explicitly development-only action; the future confirmatory analysis must not silently run prospective sizing from final outcomes. No change to frozen N or hypothesis based on final observations.

Acceptance: regression cases for absent B16, a 1-of-16 grid, duplicate query replacing a missing query, wrong world/query identity, missing family, missing/failed null and malformed exact counts; S1 missing queries and measured/nonmeasured RSS; fixture phase rendering. On the preserved full raw data, S2 scientific estimates and per-world scores must remain unchanged; enumerate expected corrected metadata differences. S1 correctness/completion remains unchanged while RSS becomes truthful.
